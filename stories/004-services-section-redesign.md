# Story 004 - Services Section Redesign

## Status
`done`

## Objective
Redesign the services/capabilities section so it feels materially more premium, curated, and compatible with the hero.

## Context
Capability presentation is one of the most important trust-building areas of the portfolio. If the section feels generic, repetitive, or template-like, it lowers the perceived maturity of the whole site.

## In Scope
- redesign the services/capabilities section layout
- improve heading and subheading hierarchy
- improve grouping of capability statements
- refine supporting copy if needed
- improve the section’s visual rhythm and spacing
- improve responsive behavior for this section

## Out of Scope
- hero redesign
- selected work/projects redesign
- technical depth/studies redesign
- final CTA/contact redesign
- footer redesign
- site-wide motion system changes

## Acceptance Criteria
- the section feels more premium than before
- the section feels visually compatible with the hero
- hierarchy is clearer
- capability presentation feels curated instead of dumped
- the section does not resemble a generic template block
- desktop and mobile layouts remain coherent
- no fake claims or inflated proof are introduced

## Likely Files
- the services/capabilities section component
- related content/data file if one exists
- any shared section wrapper or layout helper used by the section
- relevant styles/utilities in the current UI structure

## Dependencies
- `PRD.md`
- `brand.md`
- `decisions.md`
- Story 003

## Validation
- run relevant lint/typecheck/build commands if code is changed
- manually verify the section on desktop
- manually verify the section on mobile
- confirm spacing and contrast feel aligned with the hero
- confirm content remains credible and grounded

## Implementation Notes
- avoid too many equal-weight cards
- prefer fewer stronger groups
- preserve the dark premium identity
- do not overcomplicate the section with decorative elements
- aim for clarity, authority, and compositional strength
