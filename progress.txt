- Implement exactly one story per iteration
- Only set `passes: true` in `prd.json` after implementation is complete and all relevant checks pass
- Append to `progress.txt`; never rewrite previous history

- All content should come from JSON files in `data/`, not be duplicated across components
- Use `next/font` for display/body fonts and expose them as CSS variables for consistent Tailwind usage
- Theme tokens should be defined centrally and reused consistently across components
- Maintain the dark editorial premium aesthetic: burgundy-dominant backgrounds, cream/light surfaces, strong serif headings, disciplined spacing
- Projects must be presented as selected work/case-study style cards, not as a generic image gallery
- Use Framer Motion for section entrances and scroll-driven effects; keep hover states in CSS/Tailwind
- Respect `prefers-reduced-motion` for all non-essential animations
- Prefer `transform` and `opacity` for motion; avoid layout-triggering animation properties
- Before committing, inspect `git status` and avoid including unrelated changes
- If checks fail, do not commit; record the failure and blocker in the progress log
- Do not expand scope beyond the selected story; log follow-up ideas instead of implementing them immediately
